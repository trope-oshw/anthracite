# Anthracite firmware

Firmware for the STM32F030C8T6 on the control board. It reads the panel
toggles and MIDI, and drives the analogue switches and the indicator LED. It
never handles audio — the signal path is analogue throughout.

## Why these instructions exist

This firmware is licensed under **GPL-3.0-or-later**. That licence asks that if
you receive a device with GPL software on it, you are able to replace that
software with your own modified version. So the procedure is documented here,
and the SWD header is left accessible and unlocked on shipped units.

You do not need any of this to use the pedal.

## What you need

| | |
|---|---|
| Probe | ST-LINK/V3 (V3MINIE or similar) with SWD |
| Toolchain | CMake ≥ 3.22, Ninja, `arm-none-eabi-gcc` |
| Flashing | `STM32_Programmer_CLI` (or OpenOCD) |

Installing **STM32CubeIDE** gives you all four; nothing else is required.
The released binary was built with CMake 3.28.1, GCC 14.3.1 and
STM32_Programmer_CLI 2.22.0.

## Building

```sh
cmake --preset Debug
cmake --build --preset Debug -j
```

The ELF lands in `build/Debug/`.

Do **not** substitute a hand-written `cmake -S . -B build -G Ninja …` command:
it omits `-DCMAKE_TOOLCHAIN_FILE` and the configure step will fail. Use the
presets.

> **The shipped binary is built with the `Debug` preset (`-O0 -g3`).**
> This is deliberate for the first production run — the frozen image was
> validated at that optimisation level and re-optimising would invalidate the
> acceptance test. `Release` (`-Os -g0`) builds and runs, but has not been
> through the same validation. Build `Debug` if you want to reproduce the
> shipped image exactly.

## Flashing

The SWD header is **J101**, a 14-pin STDC14 connector (2×7, 1.27 mm pitch) on
the control board. Pins 3/4/5/6/12 carry 3V3, SWDIO, GND, SWCLK and NRST; pins
13/14 are a serial console.

```sh
# Check the probe sees the target
STM32_Programmer_CLI -c port=SWD

# Write, verify, reset
STM32_Programmer_CLI -c port=SWD freq=4000 -w build/Debug/<project>.elf -v -rst
```

The ELF carries its load address, so no address argument is needed. With OpenOCD:

```sh
openocd -f interface/stlink.cfg -f target/stm32f0x.cfg \
        -c "program build/Debug/<project>.elf verify reset exit"
```

If the probe is not found: close any CubeIDE debug session first — it holds the
ST-LINK open. With more than one probe attached, select it with `sn=<serial>`.

## Verifying a build against the shipped image

Comments and debug information do not affect the flash image, so a source tree
that differs only in comments should produce an identical binary. To check:

```sh
arm-none-eabi-objcopy -O binary build/Debug/<project>.elf firmware.bin
sha256sum firmware.bin
```

Compare against the checksum published with the corresponding release. Compare
the `.bin`, not the `.elf` — the ELF contains DWARF debug information that
carries line numbers, so it changes when comments move even though the
programmed image does not.

## Third-party code

`Drivers/` contains code from STMicroelectronics and ARM, under their own
licences (ST HAL: BSD-3-Clause; ARM CMSIS: Apache-2.0). Those files carry their
own SPDX headers, which take precedence over the directory-level declaration in
`REUSE.toml`. Files generated by STM32CubeMX and left unmodified are not claimed
as ours.
