# Anthracite firmware

Firmware for the STM32F030C8T6 on the control board. It reads the panel
toggles, the footswitch and MIDI, and drives the analogue switches and the
LEDs. The audio signal never passes through the microcontroller.

This tree is firmware 1.1.0, the version on Anthracite v1.1 units.

## Which firmware for which board

Each firmware version is for one board revision. Trope does not promise
compatibility between them:

| Board | Firmware | Source |
|---|---|---|
| v1.1 | 1.1.0 | this tree |
| v1.0 | 1.0.0 | tag [`firmware-1.0.0`](https://github.com/trope-oshw/anthracite/tree/firmware-1.0.0/firmware) |

Do not put 1.0.0 on a v1.1 board. The MIDI OUT jack doubles as the
external-switch input, and both use its Tip. On v1.0, U108 disabled the MIDI
OUT driver in external-switch mode (DIP-SW3 off). v1.1 removed U108, so no
hardware gate sits between the driver and the Tip, and only the firmware keeps
MIDI OUT silent in that mode. 1.1.0 checks the mode in every path that sends
on MIDI OUT, including the `MSEND` console command, and when DIP-SW3 is turned
off it waits out a byte still being sent before it reads the Tip. One
exception: while the serial console's DBG mode is on, the firmware stops
reading the DIP switches, so if DIP-SW3 is turned off during DBG, `MSEND` and
Thru can still send on the Tip. Leave DBG mode before changing DIP-SW3.
1.0.0 also mutes Active Sensing and Thru in that mode, but it leaves `MSEND`
and a byte still being sent to U108.

1.1.0 has not been tested on a v1.0 board.

## Why these instructions exist

This firmware is licensed under **GPL-3.0-or-later**. That licence asks that if
you receive a device with GPL software on it, you are able to replace that
software with your own modified version. Trope documents the procedure here
and leaves the SWD header on shipped units accessible and unlocked.

You do not need any of this to use the pedal.

## What you need

| | |
|---|---|
| Probe | ST-LINK/V3 (V3MINIE or similar) with SWD |
| Build | CMake 3.22 or later, Ninja, the GNU Arm toolchain (`arm-none-eabi-gcc`) |
| Flashing | `STM32_Programmer_CLI` (or OpenOCD) |

STM32CubeIDE ships CMake, Ninja, the GNU toolchain and `STM32_Programmer_CLI`
in `STM32CubeIDE/plugins/com.st.stm32cube.ide.mcu.externaltools.*/tools/bin`.
With those directories on `PATH`, you have every tool the build and flashing
steps use.

## Building

Run these commands in the `firmware/` directory, where `CMakePresets.json` is:

```sh
cmake --preset Debug
cmake --build --preset Debug
```

The ELF is `build/Debug/anthracite.elf`.

Use the presets. A hand-written `cmake -S . -B build -G Ninja …` command omits
`-DCMAKE_TOOLCHAIN_FILE`, and the configure step fails.

On Windows, CMake warns when object file paths approach 250 characters. Clone
the repository to a short path if you see that warning.

## Reproducing the shipped image

Units carry the `Debug` build (`-O0 -g3`) of their firmware version. Built
with the tools below, the `Debug` preset reproduces that image byte for byte:

| Tool | Version |
|---|---|
| GNU toolchain | GNU Tools for STM32 14.3.rel1.20251027-0700 (GCC 14.3.1), bundled with STM32CubeIDE 2.1.0 |
| CMake | 3.28.1 |
| Ninja | 1.11.1 |

```sh
arm-none-eabi-objcopy -O binary build/Debug/anthracite.elf anthracite.bin
sha256sum anthracite.bin        # Linux, Git Bash
shasum -a 256 anthracite.bin    # macOS
```

In PowerShell, `Get-FileHash -Algorithm SHA256 anthracite.bin` prints the same
hash in upper case.

The flash image is loaded at `0x08000000`:

| Firmware | Board | Size | SHA-256 of `anthracite.bin` |
|---|---|---|---|
| 1.1.0 (this tree) | v1.1 | 42,680 bytes | `c3b4315e6ef8f41003b9ee5af9f5c4985d8db9394cf867170972df821abfd338` |
| 1.0.0 (tag [`firmware-1.0.0`](https://github.com/trope-oshw/anthracite/tree/firmware-1.0.0/firmware)) | v1.0 | 42,516 bytes | `b7581d1ae76084e6236442fdeab6e39d7fa7e3c6bd3c1cf8cb9a229a08162016` |

To check 1.0.0, check out the tag and build it the same way.

Compare the `.bin`. The ELF also holds debug information with line
numbers and file paths, so it changes when comments move or the tree sits in a
different directory, while the flash image stays the same. A different
compiler version can produce a different image.

`CMakePresets.json` also defines a `Release` preset (`-Os -g0`). It produces a
different image from the one on Trope's units.

## Flashing

The SWD header is **J101**, a 14-pin STDC14 connector (2×7, 1.27 mm pitch) on
the control board. Pins 3/4/5/6/12 carry 3V3, SWDIO, GND, SWCLK and NRST; pins
13/14 are a serial console.

```sh
# Check the probe sees the target
STM32_Programmer_CLI -c port=SWD

# Write, verify, reset
STM32_Programmer_CLI -c port=SWD freq=4000 -w build/Debug/anthracite.elf -v -rst
```

The ELF carries its load address, so no address argument is needed. With OpenOCD:

```sh
openocd -f interface/stlink.cfg -f target/stm32f0x.cfg \
        -c "program build/Debug/anthracite.elf verify reset exit"
```

Trope programmed the v1.0 and v1.1 units with STM32_Programmer_CLI 2.22.0.

If `STM32_Programmer_CLI` reports no ST-LINK, close any CubeIDE debug session
first: it holds the ST-LINK open. With more than one probe attached, select one
with `sn=<serial>`.
